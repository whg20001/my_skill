# 增强型 Markdown + 交互式 SVG：知识点与架构的默认讲解方式

## 使用时机与优先级

用户已明确偏好：优先采用支持 HTML、iframe、脚本或组件扩展的增强型 Markdown，并配合交互式 SVG 讲解知识点、模型架构、张量流、机制与条件变化。主要阅读环境是 Obsidian、VS Code、Typora 等本地编辑器。交互应回答具体问题，例如“只改变语言条件，动作如何变化”“这个模块接收和输出什么”“训练与推理经过哪些分支”。简单事实无需配图；用户指定其他格式时遵循用户要求。

## Markdown 与交互承载

优先级为：**已验证可运行的内联 HTML / iframe / 已有脚本或组件扩展 + SVG → 独立 HTML / SVG 交互版 → 静态或动画 SVG 图片 → 必要时普通流程图**。结合实际编辑器选择，不为了固定形式安装额外框架。

Markdown 可以显示自动播放动画，有些查看器的 HTML 或组件扩展也支持完整交互。不要笼统断言“MD 不能动画/交互”。应区分：自动播放（GIF、APNG、SVG 的 CSS/声明式动画等）、用户驱动交互（点击、拖动、参数变化）、图像与文档嵌入上下文。

`![说明](path.svg)` 通常将 SVG 作为图像加载，脚本不会执行，内部链接和控件不具备完整交互；但某些无脚本动画仍可能播放。SVG 作为独立文档或 HTML 内联 SVG 时具有不同能力，仍受宿主权限约束。不要承诺所有查看器都支持内嵌，也不要要求关闭安全限制。

默认产物包含 `assets/<topic>.svg`（无脚本状态仍能表达核心关系，可带直接打开时使用的交互）和 `assets/<topic>.html`（内联 SVG 及自包含 CSS/JavaScript）。MD 优先嵌入已支持的交互载体，提供“打开交互版”链接和无需脚本的 SVG 预览回退。可以用 `<details>` 收起重复的回退图。

路径保持对应关系并检查引用能够找到文件。根据宿主使用绝对或相对路径；搬移文件时携带资源并更新路径。若 SVG 图像本身不受支持，可额外提供 PNG。不得把“写入 iframe 标签”“浏览器中可运行”或“通过结构检查”当作“所有编辑器均已实测”。

## 本地编辑器适配

| 环境 | 选择依据 |
|---|---|
| Obsidian | 官方支持 iframe 嵌入网页；库内 HTML、本地路径、已有插件的支持另行核查，不假定任意相对 HTML 链接能直接嵌入 |
| VS Code | 内置 Markdown 预览默认限制脚本；已有 Markdown 扩展可以增加渲染和脚本能力。若未配置相应扩展，提供浏览器交互版回退，不建议关闭预览安全限制 |
| Typora | 官方支持 HTML 与 iframe 嵌入；本地文件、脚本及导出后的行为按实际版本验证 |

不要擅自安装插件或修改编辑器设置。用户明确要求配置时，再在对应任务中处理。具体兼容结论应基于官方文档或实际测试，随版本变化重新核查。

## 图中表达什么

先给全景，再允许选取单个模块。必要信息包括输入输出、张量形状、训练/推理关系，以及原文 §/Eq./Fig./Table 锚点。模块说明应讲清目的、运算、去向与边界，不能只做“悬停换颜色”的装饰。

参数或规则变化必须产生可解释的视觉结果。明确区分论文事实、教学整理、自拟数值、未报告细节；不要把预设标签驱动的演示说成实时模型推理，不要伪造脑电波形、注意力权重、模型概率或神经生理证据。

## 科研 SVG 默认样式（用户偏好）

完整架构图的样式固定在 `architecture-style.md`，当前规范的完整样例为 `../assets/architecture-style-reference.svg`。绘制完整模型、训练流程或参数继承总览时，先读该规范并查看样例；复用视觉，不复用样例的具体方法与结论。生成用 `../scripts/svg_figure_kit.py`，检查与渲染用 `../scripts/check_figure.py`。

风格选择优先级：**当前用户明确指定的参考图 → 已查看的论文框架图 → 以下默认样式**。这个优先级只改变视觉呈现，不覆盖论文的数学、模块拓扑、训练关系与证据边界；风格参考不是被分析论文的方法来源。

- **版式**：优先横向主数据流或“左侧表示/运算、右侧融合/输出”的期刊式布局。多阶段训练可上下对照，纵向表示阶段衔接，横向表示阶段内部计算。宽图在小屏允许图内横向滚动，不让正文与控件溢出。
- **背景与分区**：白底；模块按模态填充低饱和底色并带同色细边，训练图中可训练 / 冻结用边框加标签区分（`architecture-style.md` §2）；论文接口、自拟算例、训练阶段等逻辑组用细灰虚线框分隔。避免过多嵌套框、厚边卡片、阴影、渐变和仪表盘装饰。
- **矩阵与张量**：细黑格线、清晰的行/列标签和 shape；长维度用省略号，不绘制上千个格子。少量低饱和颜色区分 token 来源，**同一颜色在整张图里只表示一种含义**，并在图例中说明。不以颜色暗示未验证的数值、注意力或生理机制；矩阵示意不是实测热图，必要时明示。
- **箭头**：前向数据流用蓝色实线；标签 / 参考答案进入损失用深灰实线（监督线）；梯度回传和参数继承分别用棕色虚线、灰色点线，并提供图例。图例中出现的线型，图上必须有对应的线。
- **字体与层级**：英文优先 Times New Roman，斜体变量用 Cambria，中文优先宋体 / Noto Serif CJK，提供回退。模块名加粗，变量斜体、数字正体，上下标用 `tspan dy`。最终尺寸下正文不小于 7 pt（换算见 `architecture-style.md` §3.1），不靠缩小字号硬塞内容。
- **内容密度**：图内只放模块名、核心算式、输入/输出、shape 与权重来源；“非…”“不…”式的免责注释、未报告项和推断出的机制统一写进图底部的编号图注，长解释放进交互面板。公式旁放矩阵、向量和中间结果，不只堆文字。
- **交互层**：静态 SVG 的关键结构与结果始终可读；控件位于图外。选中高亮用深蓝粗描边，**不用橙色**（橙色在训练图中表示可训练），也不遮盖公式；切换明确展示当前训练模块、输入条件或计算步骤。
- **证据标注**：已核实原图才可称“依据 Fig.X 重绘”；只有文字/公式时写“教学示意，非原图复刻”。原文事实、教学简化、自拟数值和未报告结构显式分开；不把参考图中的 CSP、稀疏惩罚等模块带入无关论文。

建议使用 viewBox 与统一间距，必要时拆分总览和局部放大图。配色默认值见 `architecture-style.md` §2 与 `svg_figure_kit.py` 中的 `FILLS`；它们只是视觉默认值，不是固定学术语义。与原文含义冲突时应调整并提供图例。

## 贴近论文框架图的视觉风格

绘制前先查看相关 Fig. 的原始页面或清晰截图，记录图号和视觉约定：阅读方向、分组与分支、模块位置、颜色对应含义、边框/线型、箭头、张量画法与标注层级。无用户风格覆盖时，以论文图作为交互版的视觉基准；用户指定参考风格时，以原文为结构与语义依据、参考图为视觉依据，并说明重排或教学重绘。让读者能在两者之间找到同一模块；不要默认改成通用仪表盘、渐变卡片或无关的流程图风格。

- 保留原图的模块命名、拓扑和颜色语义。原图未定义颜色含义时，不自行给颜色赋予“冻结/可训练”等事实含义；训练状态依据正文写明的训练设置，用边框加标签表示并进图例。新增高亮与教学标记也用单独图例说明。
- 在相同框架上叠加选择、高亮、展开与数据流演示。按钮和说明面板放在图外或预留位置，不遮挡原图结构；不要为了动画改动真实依赖、合并顺序或训练/推理分支。
- 可为中文可读性、对比度与小屏显示调整字号、间距和布局；若简化或重排，标明“依据 Fig.X 的教学重绘”及省略项。视觉相似不能牺牲数学准确性。
- 论文有多张框架图时，以所讲模块对应的图为准，整体保持一致。公式微演示沿用所属模块的颜色和符号，不另外引入不相关的设计语言。
- 未提供框架图、原图看不清或仅有文字时，使用简洁学术风格并注明“教学示意，非原图复刻”，不声称已贴近未查看的原图。

## 公式旁的小型动态演示

对矩阵乘法、投影、注意力、归一化、卷积、损失聚合等适合逐步计算的重要公式，优先在公式附近提供紧凑的 HTML + SVG 微演示。一个演示聚焦一个运算链，帮助读者回答“输入是什么、先做什么、接下来怎么算、最终得到什么、输出送到哪里”。简单定义或纯理论命题不必硬套矩阵动画。

1. **输入**：保留原式与 Eq./模块锚点；展示一个可手算的小矩阵/向量、轴含义与形状。实际张量维度与教学缩小维度分别标注，所有自拟数据和权重显著标为教学示例。
2. **当前步骤**：高亮公式中的当前算子和参与计算的行、列或元素，同时显示具体算式。区分矩阵乘法、逐元素乘法、转置、reshape、拼接和广播；明确 softmax/归一化沿哪一轴进行。拆成串行帧是教学顺序，不代表硬件串行执行或真实运行耗时。
3. **中间量**：计算完成后保留数值与 shape，让读者看到输入如何变成中间结果。多阶段公式逐步展示，例如 QKᵀ → 缩放 → mask（仅在所讲式子采用时）→ softmax → 乘 V；不擅自插入原文未给出的层或激活函数。
4. **输出**：明确展示完整最终矩阵/标量、其含义与下一模块，和正文 toy example 使用同一组数值。泛写 fθ(X) 的公式不能据此虚构内部算子；可单独展开有标记的背景例子，并指出与实际模块的差别。
5. **控制**：默认可停在输入帧，支持上一步、下一步、播放/暂停与重置，显示步骤编号。若开放参数编辑或预设切换，下游数值与高亮必须一起重新计算，并检查输入有效性；无需为了交互强加参数控件。
6. **兼容**：无脚本/减少动态效果时仍能查看输入、关键中间量与最终输出，可用静态多帧或表格回退；不要只留一个无法推进的初始帧。动画配文字解释，不以移动的箭头替代计算过程。

### 微演示设计例：线性投影（自拟，非任何论文原式）

对 Y = XW，取 X = [[1, 2], [3, 4]]（2×2）、W = [[1, 0, 1], [0, 1, -1]]（2×3）。先高亮 X 的第一行和 W 的第一列，显示 y₁₁ = 1×1 + 2×0 = 1，再逐格填充 Y，最终为 [[1, 2, -1], [3, 4, -1]]（2×3）。输出解释为每一行从 2 个特征投影成 3 个特征，行数保持不变。此示例只展示线性算子，不能直接冒充论文中的完整 MLP；若论文另含偏置、激活或多层结构，按实际公式补充或明确缩小了范围。

## 实现与验证

保持资源自包含，通常不需要外部库、网络、遥测或远程数据请求。SVG 使用 `viewBox`、可辨认字号、`title`/`desc`、充分对比度。可点击元素支持键盘，但 `role="button"`、`tabindex` 只由 HTML 中的脚本添加，静态 SVG 不带这些属性。默认状态信息完整，面板不能遮挡文字；动画应可暂停，并尊重减少动态效果的系统偏好。

先运行 `python scripts/check_figure.py <图>.svg --render <预览>.png --slices 3 --html <图>.html`：没有 ERROR、HTML 自检通过之后，再逐段查看渲染切片。打开交互版验证主要状态切换、模块选择与键盘操作，检查每条输出与原文编码一致。检查脚本错误和小屏布局，渲染后目视检查。对公式或 toy example 的计算单独核算，并检查初始、中间、最终帧与公式一一对应，逐步/自动播放得到相同结果，回退、重置和修改输入后没有残留的旧数值。将交互图与实际查看过的论文框架图并排核对，确认模块、连线、颜色语义和标注一致；仅布局相似不算通过技术核查。图仅辅助讲解，不能替代必要公式、证据索引和数据表。
