# 完整架构图风格：模型结构 + 多阶段训练的科研总览

## 使用范围、样例与工具

| 资源 | 用途 |
|---|---|
| `../assets/architecture-style-reference.svg` | 本规范的完整样例（E²-LLM：模型结构、三阶段训练、关键结果）。训练状态编码、监督线、穿过冻结模块的梯度、跨阶段继承、图注写法都以它为准 |
| `../scripts/svg_figure_kit.py` | 生成器工具：模态填充、状态边框与标签、五类连线、公式标记（上下标/斜体）、图例、图注、SVG + HTML 一并输出 |
| `../scripts/check_figure.py` | 机械检查与渲染：XML、id 引用、静态 SVG 中残留的交互属性、打印字号下限、框内免责注释、图注是否存在；可渲染 PNG 切片并运行 HTML 自检 |

样例只规定**视觉语言与读图方式**，不是通用网络结构。新论文必须依据自己的原文决定模块、阶段、张量、训练参数和验证范围，不得复制样例中的模型名、维度、token 数或实验数值。

优先级：当前用户指定参考图 → 已查看的当前论文框架图 → 本样式。用户要求沿用此风格时，用当前论文确定结构、本规范确定视觉。无原图依据时标明“教学示意，非论文原图复刻”。

## 1. 全景布局

- **顶部**：论文/模型名、一句话输入输出关系；下一行说明各区的视角（例如“A：推理时的模型结构　B–D：三阶段训练（参数更新视角，不是另一条串联网络）　E：关键结果”）。
- **A 区，模型结构（推理时）**：从左到右为输入 → 编码 → 接口 → 主干 → 输出；另一模态从下方独立分支接入，合流位置以原文为准。每个带参数的模块用底部标签写出**推理时使用的权重来源**（如 `权重 θ₁`、`权重 ψ₃`、`权重 ω + LoRA`），A 区右上角再汇总一行。这样训练区和模型区才能连起来。
- **训练区，每阶段一行**：阶段内部横向计算，阶段之间纵向衔接。
  - **同一模块在各阶段放在同一列**（编码器一列、接口/分类头一列、主干一列、损失一列）。某阶段不涉及的模块留空列，并用灰字注明（如“Projector / Qwen3：冻结，不在此路径”），不要让别的模块错位占用这一列。
  - 每行分上下两层：上层是模块链，下层放这一阶段的其他输入（问题文本、标签 / 参考答案）。阶段之间的空带用来写继承标签。
- **结果区**：架构图默认不放结果。若要放，优先放**支撑架构设计的证据**：随机 / 已有基线、逐个去掉各组件或阶段的消融，并写清样本数和指标名。不要只挑一个最好看的数字。
- **画布**：宽度和字号一起决定（§3.1）；推荐宽 1600、高度按内容定。内容放不下时拆成总览图加局部图，不缩字号。

## 2. 编码：填充色表示模态，边框表示训练状态

| 元素 | 画法 | 含义 |
|---|---|---|
| 信号侧模块 | 浅蓝填充 `#E4EEF8`、蓝边 `#5B87B8` | EEG / 图像 / 语音等编码路径 |
| 接口模块 | 浅紫 `#EEE7F6`、紫边 `#8A6FB0` | Projector、adapter、融合接口 |
| 文本侧模块 | 浅绿 `#E5F2E6`、绿边 `#5E9A64` | 文本、tokenizer、词嵌入 |
| 主干 | 浅黄 `#FBF1D3`、黄边 `#B8973A` | LLM、解码器、策略网络 |
| 数据 / 损失 / 标签 / 无参运算 | 白底、灰边 `#9AA5B1` | 不含可训练参数 |
| **可训练** | 橙色实线粗边 `#C8743A` 3 px，左上角实心橙色标签“可训练” | 本阶段更新参数 |
| **冻结** | 灰色虚线边 `#6F7C8B` 2.2 px、`8 5`，左上角描边标签“冻结” | 本阶段参数不更新 |
| 混合状态 | 外框按冻结画，内部嵌一个可训练小框 | 例如基础权重冻结、只训练 LoRA |
| 交互选中 | 深蓝粗描边 `#1F3A5F` | 只在 HTML 中出现；**不用橙色**，橙色已表示可训练 |

- **训练状态绝不能只靠文字**（例如在框里写 TRAINABLE / FROZEN）。读者应当扫一眼就分得清哪些模块在更新。
- 状态只能依据原文写明的训练设置来标；原文没说的写进图注，不要猜。
- **同一种颜色在整张图里只表示一种含义**，矩阵格和 token 条也不例外。例如不能在 patch 网格里用颜色区分通道，又在拼接序列里用同一套颜色区分来源。新增颜色必须进图例。
- 状态标签放在左上角，右上部留给跨阶段继承箭头落点。

## 3. 文字与排版

### 3.1 字号下限

最终尺寸下的字号 = 画布字号 × 排版宽度 ÷ 画布宽度。正文和注释至少 7 pt，上下标可以按 70% 另计：

| 画布宽 | 双栏通栏（504 pt）下的最小字号 | 单栏（241 pt）下的最小字号 |
|---|---|---|
| 1600 | 23 px | 47 px |
| 1920 | 27 px | 56 px |

`svg_figure_kit.min_font_px(width, target_width_pt)` 可以直接算；`check_figure.py` 会逐条检查。只在屏幕上看的笔记图也按通栏宽度校验：屏幕适应宽度显示时，效果和印刷差不多。拥挤时应删内容、拆图或加宽间距，不要缩小字号。

### 3.2 图内只放结构，说明集中到图注

- 模块框内按“名称 → 核心运算 / 公式 → 输出 shape → 权重来源或状态”排列，最多 3–4 行。
- **框内不写免责式的元注释**，例如“非图像”“连续向量，非词 ID”“不补造内部层”“不是分类头”“反传线为机制示意，不是代码执行轨迹”。这类话是写给作者自己的阅读批注，会冲淡结构。
- 图底部写编号图注，集中交代四类信息：
  1. 依据哪些 Fig. / § 重绘、省略了什么（如 batch 维），以及推算出的 shape；
  2. **原文未报告**的超参数和结构（如 patch 长度、读出方式、初始化）；
  3. **由训练设置推出、原文没有直接说**的机制（如梯度穿过冻结的 LLM），注明“推断”；
  4. 证据边界（划分协议、离线评测、不构成临床验证等）。
- 每个模块的完整解释写进 HTML 的说明面板（即 `box()` 的 `detail` 参数），同时作为 `<title>` 提示框。提示框只能做补充，不能是关键信息的唯一出处。

### 3.3 语言、符号与公式

- **语言统一**：固定为“英文模块名 + 中文说明”，或全中文。分区标题、图例和注释都遵守同一规则。
- **一个对象只用一套记号**：例如编码器各处都写 `ENC_θ`，Projector 都写 `P_ψ`，不在 A 区写 `ENC`、在训练区写 `E_θ₁`。参数版本统一写成 θ₁、ψ₂ → ψ₃。
- **上下标**：用 `<tspan dy>` 加 70% 字号（工具的 `_{…}` / `^{…}` 标记）。`baseline-shift` 有的浏览器不支持；也不要和 Unicode 下标字符（ₑ、₁）混用，否则同一张图里会出现两种下标。
- **正体与斜体**：变量用斜体（`*x*`），数字、单位和函数名（softmax、log、ENC）用正体。不要给 `58 × 1024` 整串套斜体。斜体用 Cambria：Times New Roman 的斜体 z 在小字号下像 ʒ。
- **特殊 token 和代码**用等宽字体并原样显示，例如 `<eeg_start>`。

## 4. 五类连线与端口

| 连线 | 画法 | 语义 |
|---|---|---|
| 前向计算 | 蓝 `#4F7FB8` 实线 2.6 | 数据或表示的传递 |
| 监督信号 | 深灰 `#333` 实线 2 | 标签 / 参考答案进入损失 |
| 梯度回传 | 棕 `#B0652F` 虚线 2.2、`9 5` | 训练时的梯度路径，属于机制示意 |
| 参数继承 | 灰 `#7D7D7D` 点线 2.4、`2 6`、圆端 | 跨阶段复制或沿用权重 |
| 模型选择 | 用参数继承的画法另加标签 | 例如挑选 checkpoint |

- **每个训练阶段都要画出一条样本的全部组成部分**：信号进编码器，问题文本进主干（可以注明“经 Embedding，见 A 区”），标签或参考答案用**监督线**进损失。标签不能只写成损失框里的一行字；图例里出现的线型，图上必须真有对应的线。
- **梯度线与前向线平行、方向相反**，画在模块之间的空隙里。例如前向线在框顶下 50 处，梯度线在框顶下 100 处。这样不需要额外的走线带，也不会和纵向的继承线交叉。箭头指向接收梯度的模块。
- **梯度要经过冻结模块才能到达上游可训练模块时**（例如“冻结 LLM、训练 Projector”），梯度线必须画成**进入再离开**这个冻结模块，不能从下方绕过去。冻结边框已经说明它不更新；如果原文没有明说这一点，就在图注里标为推断。
- **每一组被继承的参数都画一条继承线**，包括全程冻结的预训练主干（如 ω）。继承线落在模块上边缘的右部，避开左上角的状态标签；标签（如“θ₁ 继承，此后冻结”“ψ₂ 继续训练”“ω 不变 + LoRA”）写在阶段之间的空带里。
- **分区标题要短**（如“C　Stage 2：跨模态对齐”），以免和纵向继承线相交。数据量、任务类型这类细节写进数据框；原文锚点在标题行右对齐。
- 箭头使用 `markerUnits="userSpaceOnUse"` 固定尺寸，三角形 `viewBox="0 0 10 10"`、`refX="10"`、`refY="5"`、`orient="auto"`；路径终点与模块边界重合。
- 每个输入、输出各有自己的端口，多条线不挤同一点。优先用正交折线，避免共线重叠、穿过模块或文字。真正共享的干线可以分叉，在分叉点画小圆点；不相关的交叉尽量绕开。
- 回传只连到原文支持的可训练模块，继承只连到真正保留下来的参数；删掉的训练头不能出现在推理链里。

## 5. 内容完整性：对照论文逐项检查

- **论文的贡献点和被消融证明重要的组件，都要在图上看得见**。例如：回答格式本身是贡献（CoT 先描述后结论），就把它画进输出框；只列任务名不够。
- **每种嵌入的来源要画清楚**：特殊 token（如 `<eeg_start>`）来自词表、经 Embedding；连续向量来自 Projector、不经 tokenizer。用 token 条示意拼接时，每种来源一种颜色并配图例。
- **任务需要多份输入时**（一条序列含 2–3 段 EEG、多张图像、多轮对话），在序列示意里至少画出两块，不要只写在文字里。
- **阶段名称要贴合原文实际做的事**：在预训练模型上用分类目标微调，写“情绪判别微调”，不要只写“预训练”；原文另有叫法时可以在说明面板里注明。
- 拼接、相加、投影、切片等算子要区分开；矩阵着色只是示意，不能冒充实测数值、注意力或激活热图。
- 损失、监督、训练标签与推理输入不能混淆；省略 batch 维时统一说明。

## 6. 交互与交付

- **用脚本生成**：在笔记的 `assets/` 下放 `build_<topic>.py`，用 `svg_figure_kit.Figure` 一次输出 `<topic>.svg` 和 `<topic>.html`，再渲染出 2× PNG。三者都从同一个脚本生成；之后要改图时改脚本，不要手改生成出来的文件。
- **静态 SVG 不带 `role="button"` 或 `tabindex`**：作为图片嵌入时它们无法交互，还会误导屏幕阅读器。这些属性由 HTML 里的脚本在运行时添加（工具的 HTML 模板已经这样做）。
- HTML 的控件放在图外：可以按分区切换视角、选择模块，并在说明面板显示“输入、运算、输出、更新状态、原文依据”。HTML 自带 `?test` 自检。
- **每个分区都写 `summary`**（`fig.section(..., summary="…")`）：切换到该视角时，说明框显示这一分区的概要，包括数据、哪些模块更新、得到什么权重、原文锚点。没写概要时，说明框只列出分区里的模块名；如果分区里连模块都没有（比如纯文字的结果区），自检会失败，提醒你补上概要。“完整总览”显示 `Figure` 的 `desc`。
- 静态图本身必须完整可读。移动端允许图内横向滚动；只报告实际验证过的查看器支持。

## 7. 绘制后验收

1. **对照论文**：逐个核对模块、输入分支、合流位置、shape、每阶段的数据组成、监督路径、更新范围、继承关系，以及阶段名称。样例内容不能当证据。
2. **完整性**：检查贡献点和消融组件是否可见，嵌入来源是否画清，多份输入是否画出；A 区每个模块是否标了权重来源。
3. **机械检查**：`python scripts/check_figure.py fig.svg --html fig.html`，必须没有 ERROR；对 WARN 逐条判断。
4. **渲染目视**：`python scripts/check_figure.py fig.svg --render fig_preview.png --slices 3`，逐段查看：文字不重叠、不出框，上下标正常，箭头尖端贴住边框，梯度线和继承线不交叉，状态标签不压到继承箭头。
5. **交互测试**：HTML 自检通过；未实测的编辑器环境要明确说明。

## 8. 常见错误速查（来自对 E²-LLM 架构图的审查）

| 错误 | 改法 |
|---|---|
| 所有模块同一底色，可训练 / 冻结只写成小字 | 填充色表示模态，边框加标签表示状态（§2） |
| 框内堆满“非…”“不…”式的元注释 | 移进编号图注或说明面板（§3.2） |
| 论文的关键设计（如 CoT 回答格式）没画 | 对照贡献点和消融逐项检查（§5） |
| 训练阶段只画了信号输入，文本和标签没有路径；图例写了“监督”，图上却没有监督线 | 拆成上下两层，标签走监督线（§4） |
| 梯度线绕过冻结的 LLM，和“梯度穿过”的标注对不上 | 让梯度线进入再离开该模块（§4） |
| 模型区和训练区脱节，看不出推理用的是哪个 checkpoint | A 区每个模块标权重来源（§1） |
| 同一套颜色在不同地方表示不同含义 | 一种颜色只表示一种含义，并进图例（§2） |
| 各阶段的列含义不一致，损失框位置漂移 | 同一模块同一列，缺席的模块留空列（§1） |
| 有的继承线没画（如冻结的主干） | 每组被继承的参数都画一条（§4） |
| 结果区只有最好的单个数字 | 放基线、消融和样本数，或者不放（§1） |
| 18–21 px 字体在 1920 宽画布上 | 按 §3.1 的公式换算，至少 7 pt |
| `dLLM`、`Wc` 没有下标；数字被设成斜体；记号前后不统一 | 用 `_{…}` 标记，数字用正体，一个对象一套记号（§3.3） |
| 关键信息只放在悬停提示里；静态 SVG 带 `role="button"` | 关键信息直接画在图上，交互属性由 HTML 脚本添加（§6） |
