# Experiment Analysis：AI/ML 实验与证据审查

> 以“论文命题是否被实验支持”为核心，而非机械抄录 SOTA 表格。保留原始结果、对照条件、单位、结果来源。

## 1. 用 Claim–Test–Observation–Inference 阅读

对每个主要实验记录：

| 字段 | 提问 |
|---|---|
| Claim（命题） | 作者试图证明的能力或机制是什么？ |
| Test（设计） | 哪个数据集、对比方法、评估指标、测试设定用于验证？ |
| Observation（观察） | 文中原始数值/曲线或作者观察到什么？ |
| Inference（允许结论） | 在该实验条件下最多能说明什么？有什么未控制变量？ |

不要直接把原文结论作为事实重复一遍。特别区分：相关性、对照差异、因果贡献、跨域泛化。

## 2. 提取实验设置

需要在原文可核实时填写：

- **任务和数据集**：名称、版本、规模、训练/验证/测试划分、预处理、数据去重/泄漏风险。
- **评估协议**：prompt、few-shot 样例数量、生成长度、decoding、采样次数、人工评估准则。
- **模型**：基线名称、模型规模、预训练语料/步骤、是否使用额外标签/检索库/工具、微调策略。
- **资源**：训练和推理硬件、GPU 小时、FLOPs、吞吐/时延、显存、成本；不可互相替代。
- **随机性**：种子数、置信区间、标准差、显著性检验；未报告则写“未报告”，不默认多次实验。
- **指标**：名称、方向（higher/lower better）、单位、宏观/微观平均、阈值；统一精度表达。

根据论文类型选取对应字段，避免把缺失的所有工程细节都当成必然缺陷。

## 3. 主结果表的还原规则

1. 从原表抄录结果时同时记录 `指标名 + 数据集/任务 + 比较对象 + 值 + 单位 + 表号`。
2. 不将高分与低分方向搞反；例如 error/loss/perplexity 越低越好，accuracy/BLEU/ROUGE 通常越高越好，但依论文定义核对。
3. 分清**百分点差**与**相对百分比提升**：例如 accuracy 从 80% 至 84% 是 +4 个百分点、相对 +5%；不能写成“提升 4%”而不说明。
4. 对不同表、不同数据划分、不同模型规模或不同微调预算的数值，除非条件一致，否则不直接排序为“更好”。
5. 对缺失误差条、仅最佳结果等情况，记录可置信程度而不是编造显著性。
6. 不依据小差距声称“显著提高”，除非论文提供了足以支持的统计或重复性证据。

## 4. 消融实验的分析方式

对于每个被删除或替换的模块：

```text
被检验模块/机制：
Full setting：原模型及共用配置
Ablation setting：删去/替换/冻结什么，其余因素是否可比
结果变化：按原文数值、单位、指标方向列出
作者推断：论文作何解释
审查判断：结果是否隔离模块作用，有无交互效应/额外计算变化
```

若移除组件同时显著改变参数量、训练计算或数据访问方式，不能把性能差完全归因于该组件。若多模块耦合，单因素消融不足以证明独立贡献。

## 5. 常见实证风险

### 可比性

- 基线是否相同数据预算、调参次数、骨干网络、预训练步骤、上下文长度？
- 比较的是 zero-shot 与 fine-tuned 吗？是否具有一致的检索/工具/推理预算？
- 模型更大、计算更多造成的提升，是否可能解释新增模块以外的效果？

### 数据与污染

- 训练/测试重叠、重复样本、benchmark contamination 是否被检查？
- 是否使用真实 test set 作 prompt selection、early stopping 或参数选择？
- 分布外泛化结论是否真的跨数据集、时间或领域？

### 统计与稳健性

- 是否报告方差或置信区间？指标差异是否可能来自随机种子/样本规模？
- 对不同 prompt、数据子集、随机扰动、OOD 样本是否稳定？
- 有无失败案例、反例、最差群体或严重退化？

### 效率与成本

- Latency / Throughput / FLOPs / GPU memory / Energy 各自定义和测量环境是什么？
- 训练速度提升不自动等于推理吞吐提升；吞吐提升不自动等于单样本延迟改善。
- GPU 型号、batch size、上下文长度、量化策略与并发数不同会使数值不可直接比较。

## 6. 面向不同 AI 任务的特殊检查

| 类型 | 核心注意点 |
|---|---|
| 分类、回归 | 不平衡数据、AUROC/AUPRC、校准、数据切分 |
| 目标检测、分割 | IoU、mAP 定义、图像分辨率和标注质量 |
| 语言模型/生成 | 解码温度、few-shot 设置、污染风险、人工评测一致性 |
| 检索与 RAG | Recall@k、MRR、检索语料覆盖、oracle 假设、答案归因 |
| 多模态 | 模态与数据泄漏、不同模态强弱、评价基准构造 |
| 扩散/生成图像 | FID/KID、样本数、采样步数、推理开销、人类偏好偏差 |
| 强化学习 | 环境步数、随机种子、回报分布、训练交互成本、评估环境差异 |
| 公平性/安全性 | 威胁模型、指标局限、失败案例与适用情境 |

不要假定每类论文都应该使用全部指标；以论文自己的任务定义为准。

## 7. 结论强度规范

使用如下表述模板：

- **直接支持**："在论文的 [数据集/设置] 下，Table X 报告模型 A 在 [指标] 上为 [数值]，高于 B 的 [数值]。"
- **有限支持**："结果与模块有贡献的解释一致，但缺少控制 [条件] 的比较，因而不能单独归因。"
- **未被充分支持**："作者将这一现象解释为更好的泛化，但展示的实验仍局限于 [范围]。"
- **未报告**："目前可访问的正文未报告 [信息]；尚不能判断其影响。"
- **无法验证**："该表/补充材料未获取，暂不复述具体数值。"

不要把“未报告”直接等同“实际没有做”，两者可能不同。

## 8. 输出建议

优先输出一个紧凑的证据矩阵：

| 命题 | 证据位置 | 关键比较 | 证据强度 | 保留意见 |
|---|---|---|---|---|
| ... | §4 / Table X | A vs B | 直接支持/有限支持/缺失 | ... |

如有 20+ 表，按对理解核心贡献的价值筛选 3–6 个关键实验，剩余列入“已略读的实验”说明；若用户问全面实验复盘，才扩展全部表。

## 9. 最终核查

逐条检查：指标方向、单位、数值精度、比较配置、任务划分、统计假设、原文锚点、是否夸大因果或泛化。如当前仅可读摘要，除非摘要本身报告了相关数值且可核实，否则不要编造实验表。
